# Governance

## Current model

The project is initially maintained by SafeEat. Maintainers merge changes, publish releases, manage security reports, and protect benchmark integrity.

## Decision process

- Routine implementation follows reviewed issues and pull requests.
- Changes to scope, formats, privacy behavior, benchmark gates, licensing, comparison policy, or public claims require a written decision record.
- Security, privacy, and legal reviewers may block releases in their domain until a qualified human review is recorded.
- Agent recommendations do not constitute human approval.

## Roles needed before a supported release

- product owner;
- technical maintainer;
- backup release maintainer;
- benchmark/corpus steward;
- security contact;
- legal/licensing reviewer.

## Project maturity

Until a stable release policy is adopted, all APIs are experimental and no compatibility or support SLA is promised.
